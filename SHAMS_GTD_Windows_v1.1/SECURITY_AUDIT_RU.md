# SHAMS GTD Windows v1.1 — результаты первичного аудита

## Исправлено
- Electron renderer: `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`.
- Явно включены `webSecurity`, отключён запуск небезопасного содержимого и `webview`.
- Окна-попапы запрещены; навигация разрешена только на исходную страницу приложения.
- Запросы разрешений Electron отклоняются: текущему интерфейсу камера, микрофон и геолокация не нужны.
- Добавлена CSP: скрипты, стили и подключения ограничены локальным источником; запрещены object и base URI.
- Удалён inline-скрипт регистрации Service Worker: он не нужен в desktop-сборке на `file://` и мешал бы строгой CSP.
- Проверяется, что сохранённые задачи/проекты имеют ожидаемый тип массива, а язык входит в список поддерживаемых.

## Что осталось ограничением, а не подтверждённой уязвимостью
- Данные задач и проектов хранятся в `localStorage` профиля Electron. Это локально и удобно для прототипа, но нет резервного копирования, миграций и синхронизации.
- SQLite имеет смысл внедрять вместе с полноценным IPC API, схемой БД, миграциями и тестами. Добавлять `preload.js` без необходимости не следует.
- Нет CSP report endpoint, автообновления и подписи установщика.
- В архиве нет lock-файла зависимостей; версии Electron и electron-builder заданы диапазонами. Для воспроизводимых релизов нужен npm lock-файл и обновление зависимостей с проверкой совместимости.
- Не выполнялась полноценная проверка установленного Windows `.exe`, поскольку архив содержит исходный проект, а не собранный установщик.

## Сборка
На Windows с Node.js LTS:

```bash
npm install
npm run start
npm run dist:win
```

Перед публичным релизом необходимы тестирование на Windows, проверка зависимостей, резервное копирование/экспорт данных, политика конфиденциальности и code signing.
